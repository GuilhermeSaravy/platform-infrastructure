Copy `templates/project` to `projects/inventory`. The complete reusable example uses existing teams, dev/prod, cost center and slot 2. Keep name equal to the folder name, choose a unique network_slot (0–127), and review access with platform-engineering. Projects are discovered from `projects/*/project.yaml`; there is no shared project list. The platform derives dedicated /26s from the slot. Never recycle a removed slot until its resources, DNS, endpoints and integration are removed. JSON is the supported YAML subset, readable by Terraform yamldecode and Python json without dependencies.

The populated catalog/orders example is live configuration. This template is separate and does not deploy until copied into projects. Access and resource leaf files are complete. Runtime images and Azure identifiers are injected at execution time. Adding a project is configuration-only; adding an unsupported capability requires a reviewed module change. Storage currently supports one object-storage capability per project; at most one application-runtime capability is supported. Cross-project grants must be reviewed by the destination owner and platform engineering.

The January improvement adds `python3 scripts/onboard.py inventory` as an offline alternative to copying. It checks all candidate declarations and allocates a free slot before installing the new project. See docs/onboarding.md; the generator and its tests are authored but were not executed during generation.
