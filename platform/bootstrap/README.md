# Local bootstrap

This standalone Terraform root deliberately starts with local state. It requires an existing interactive Azure login and subscription Owner, or equivalent Contributor, User Access Administrator and Resource Policy Contributor authority. Supply TF_VAR_unique_suffix, TF_VAR_github_repository and sensitive TF_VAR_bootstrap_operator_object_id through the environment. Select ARM_TENANT_ID and ARM_SUBSCRIPTION_ID from your real account; do not commit them.

Initialize, save a protected local plan, review it privately and apply it manually as described in docs/startup.md. No client secret is used. The root creates backend storage, a deployment UAMI and an OIDC federated credential trusting exactly your repository's GitHub environment named platform. No workflow can create its own identity before local authentication/bootstrap exists.

State is retained in this directory, excluded from Git. Back it up encrypted off-repository immediately. Normal units use remote state; bootstrap does not silently migrate. To migrate later, back up local state, add backend.generated.tf with an empty azurerm backend, and run terraform init -migrate-state using the explicit bootstrap/terraform.tfstate key and Azure AD authentication. Exact commands and protection of the temporary backend file are in the startup guide. Never delete local state before proving the remote copy exists. Do not run another local-state apply after migration without the backend configuration.

The public state endpoint permits GitHub-hosted execution. Shared key and public blob access are disabled. Native Blob leases lock state; versioning and retention help recovery. The backend's resource group, storage account and container use prevent_destroy. Full teardown requires an intentional reviewed removal of those protections only after all other states are destroyed and backed up.

Deployment management roles initially span the subscription for this dedicated demonstration subscription: Contributor, User Access Administrator and Resource Policy Contributor. User Access Administrator is privileged and can escalate access. Configure GitHub environment reviewers and main-branch restrictions, restrict repository administration, and scope delegation to known resource groups/role conditions before a real shared production deployment. The role is never assigned to application workload identities. State data access is container scoped. This code does not manage Entra groups or memberships.
