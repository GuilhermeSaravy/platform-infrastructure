The first version is a complete manual platform foundation; later changes automate useful operator tasks without adding cloud implementations. All phases retain the audited historical tool versions. New tool versions, cloud APIs or service options need another audit before being scheduled.

After successful manual acceptance, useful backlog includes pull-request-based onboarding with explicit repository authorization, scheduled verification if requested later, stronger production deployment-role scopes/conditions, private runner/backend adaptation where required, and an audited current security/runtime upgrade. A future AWS repository would need its own implementation and tests; no cloud selector or multi-cloud abstraction is added here.
