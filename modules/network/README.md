# Shared environment network

One state owns the resource group, VNet, delegated integration subnets, Private Endpoint subnet, empty operator subnet, NSGs, route table, and Private DNS zones for one environment. Project states consume the output contract and own their workload Private Endpoints and their DNS zone groups. There is no dev/prod peering.

Project declarations are discovered from `projects/*/project.yaml`. `azure.network_slot` is a stable, unique integer from 0 through 127. The platform maps it to a `/26` integration subnet starting at slot 64 of the environment `/16`. Keep established slots unchanged; adding or removing a project does not replace the VNet. Removing a declaration removes that project's platform-owned subnet only after its integrations and endpoints have been removed separately.

The editable default ranges are dev `10.40.0.0/16` and prod `10.50.0.0/16`. `.1.0/24` is reserved for Private Endpoints and `.2.0/24` for an operator execution host. This module does not create a VM, VPN, gateway, or hosted runner. An operator must separately provide an authenticated machine with a NIC in the operator subnet and private administration, without a public IP. Merely connecting a laptop to a VPN does not place its source in the allowed operator CIDR. To use an existing VPN client range directly, the platform owner must deliberately add its reviewed source CIDR to the Private Endpoint NSG, provide routing, and integrate Private DNS; this module makes no such connection automatically.

Each runtime may reach shared Private Endpoints over TCP 443 and use Azure DNS. Other traffic into the VNet is denied. Private Endpoints accept HTTPS from the integration subnets and operator subnet; other VNet inbound traffic is denied. These rules intentionally permit network reachability between runtime clients and managed-service endpoints. Container RBAC and application authorization remain separate controls. The operator subnet permits HTTPS to those endpoints. Its inbound rules retain Azure's default private VNet allowance for trusted private administration; no public administrative allowance is added. Review and narrow that management access for your operator host before using it outside the demonstration.

The route table has no custom routes and disables BGP propagation. Azure system routes provide local VNet connectivity. App Service routes private traffic through integration; public traffic used for platform dependencies and image retrieval follows App Service's public outbound path. This foundation does not provide an egress firewall. Do not describe its NSGs as inspection or control of all internet traffic.

Use separate delegated subnets and Private Endpoint subnets. `Microsoft.Web/serverFarms` delegation is incompatible with placing a Private Endpoint in that subnet. Private Endpoint network policies are explicitly enabled so its NSG is effective. DNS zones are linked to this environment's VNet only. Zones with the same name in dev and prod are independent resources.

No Terraform initialization, plan, validation, test, or deployment has been performed. Verify the authored configuration and connectivity manually before relying on these rules.
