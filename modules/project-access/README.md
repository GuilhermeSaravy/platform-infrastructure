# Destination-owned access

One access state per destination project/environment owns human resource-group roles and workload grants. No workload resources, network, group creation or memberships are managed here. Run configuration checks first. It resolves logical teams through platform/identity-mapping and applies centrally defined profiles. It looks up source UAMIs and destination ARM containers by the version-1 naming contract, without reading source state. The destination owner commerce-backend and platform-engineering must review any grant. CODEOWNERS expresses review intent; enforce branch protection separately.

For the demonstration, apply catalog/dev and orders/dev resource units, create test data as the explicit operator, and run before-grant acceptance. Only then apply orders/dev/access. That state assigns Storage Blob Data Reader at orders exports container scope to catalog/dev/api. The restricted container and writes remain denied. Destroy the access unit to revoke; do not use Terraform -target. Human roles in the same state are also removed. Network access remains unchanged during grant/revoke. Resource RBAC is unrelated to arbitrary application HTTP authorization.
